# 开发路线图（MVP · 6 周）

> 原则：每周一个可演示的里程碑；先打通"闭环最小可用版"，再逐步打磨；成本与合规从第 1 周就纳入。

## 阶段总览

| 周 | 主题 | 核心交付 | 可演示成果 |
|---|---|---|---|
| W1 | 基础设施 | 仓库、Cloudflare 全栈部署流水线、D1 schema、认证、用户中心 | 可登录的 Web 应用部署上线，Health API 可用 |
| W2 | 诊断引擎 | 题库接入（种子数据）、智能组卷、交卷评分、掌握度模型 v1 | 新用户完成一次入测，看到诊断报告 |
| W3 | 大纲引擎 | 知识点图谱、AI 大纲生成（Zod 校验）、大纲编辑器 | 根据诊断报告生成可编辑的个性化大纲 |
| W4 | PPT 流水线 | 大纲→课件 JSON→PPTX 渲染→R2 存储→预览/下载 | 一节课的 PPT 可下载、可在线预览 |
| W5 | 数字人课堂 | Live2D 形象、TTS、口型同步、逐页讲解播放器、课堂提问 | 数字人完整讲完一节课，可中途提问 |
| W6 | 小测闭环 + 上线 | 课后小测→掌握度更新→大纲微调、压测、内容安全接入、合规清单 | 完整闭环跑通，试运营上线 |

## 阶段明细

### W1 基础设施
- [x] 技术选型与架构文档（本次已完成）
- [x] 项目骨架（schema / API 路由 / 前端壳 / CI）
- [ ] Cloudflare 账号开通：D1、R2、KV、Queues、AI Gateway
- [ ] 认证：Better Auth（邮箱+密码，`better-auth-cloudflare` d1Native 或 Drizzle adapter）
- [ ] 用户中心：个人档案（年级、教材版本、目标日期）、基础资料 CRUD
- [ ] CI/CD：GitHub Actions 自动部署 + 预览环境
- 验收：新用户注册/登录 → 填写档案 → 页面与 API 全链路可用

### W2 诊断引擎
- [ ] 题库模型落地：question / knowledge_point 表灌入种子数据（AGIEval 高考数学 + Math23K 小学 + TAL-SCQ 竞赛样例，仅作开发验证）
- [ ] 组卷算法 v1：按知识点图谱抽样（基础 40% / 中档 40% / 拔高 20%），LLM 补题（入待审池）
- [ ] 交卷评分：客观题自动判分；主观题 LLM 按评分标准评分（标记待人工复核）
- [ ] 掌握度模型 v1：Beta-binomial（先验 Beta(2,2)），输出 level + confidence
- [ ] 诊断报告页：掌握度热力图、短板排序、学习建议
- 验收：10 个真实用户走完"注册→入测→报告"，报告与人工判断一致率 ≥ 80%

### W3 大纲引擎
- [ ] 知识点图谱：初中/高中数学两大学科树（基于课标目录），seed 数据 + 管理接口
- [ ] 大纲生成：LLM（DeepSeek）输入（诊断报告 + 图谱子树 + 课时预算）→ 结构化 JSON（Zod 校验）
- [ ] 大纲编辑器：章节/课时增删改、目标编辑、重新生成局部
- [ ] 大纲版本管理：syllabus_revisions，微调留痕
- 验收：诊断报告能稳定生成结构合法、可编辑的大纲；人工可干预

### W4 PPT 流水线
- [ ] 课件 JSON Schema：页/块（文本/公式/列表/表格/例题/小结），LaTeX 公式规范
- [ ] LLM 课件生成：大纲→逐页内容（含口语化讲稿 notes）
- [ ] PPTX 渲染：PptxGenJS → R2（`ppt-assets/{userId}/{lessonId}.pptx`）
- [ ] 网页版演示器：KaTeX 渲染公式、翻页、备注显示（授课模式用）
- 验收：从大纲一键生成 12~15 页 PPTX + 网页课件，公式正确、可下载

### W5 数字人课堂
- [ ] Live2D 播放器：pixi-live2d-display 加载形象（Hiyori/Haru 开发占位），表情/动作控制
- [ ] TTS 接入：Edge-TTS（免费）生成逐页语音 → R2 缓存；预留火山/阿里云 TTS 接口
- [ ] 口型同步：Web Audio 频谱驱动 motion-sync
- [ ] 课堂播放器：课件 + 数字人 + 语音 + 字幕 + 暂停提问（文字问答）
- 验收：数字人完整讲完一节课 ≤ 30 分钟生成；提问回答流畅

### W6 小测闭环 + 上线
- [ ] 课后小测：针对本节课弱点知识点 + 间隔复习项生成 5~8 题
- [ ] 闭环微调：小测结果 → 掌握度更新 → LLM 建议大纲调整 → 用户确认应用
- [ ] 内容安全接入：文本审核（腾讯云天御/阿里云内容安全）+ Turnstile 人机验证
- [ ] 成本护栏：AI Gateway 限流、用量仪表盘、预算告警
- [ ] 压测（Workers 免费额度内）、Sentry 监控、上线合规清单走查
- [ ] 试运营：邀请 20~50 名种子用户

## 里程碑验收清单（上线前）

- [ ] 完整闭环：注册 → 入测 → 报告 → 大纲 → 数字人授课 → 小测 → 大纲微调 → 下一节课
- [ ] 未成年人数据保护：隐私政策、监护人同意流程、注销即删
- [ ] 内容安全：AI 输出全部过审，违规内容阻断
- [ ] 成本护栏：单用户月均 AI 成本可预估、可限制
- [ ] 备份与恢复：D1 定时导出到 R2；R2 生命周期策略
- [ ] 监控告警：Sentry + Workers Logs + AI Gateway 用量告警

## 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 中国大陆访问 Cloudflare 延迟/不稳定 | 高 | 静态资源靠边缘缓存；API 请求体量小影响有限；后续可加国内 CDN 或双轨部署（见技术方案 §9） |
| 生成式 AI 服务合规（备案） | 高 | 使用已备案大模型 API（DeepSeek/通义等）+ 平台侧内容安全；上线前完成法律评估 |
| 题库版权 | 中 | 生产题库 = 原创 + LLM 生成 + 人工审核；开源数据集仅用于开发验证（见资源清单） |
| LLM 生成质量不稳定 | 中 | 结构化输出 + Zod 强校验 + 失败重试 + 人工兜底（审核池） |
| 未成年人防沉迷/隐私 | 中 | 每日时长限制、监护人模式、数据最小化 |
| 成本失控（AI 调用） | 中 | AI Gateway 限流 + 单用户配额 + 用量告警 |

## 需要你拍板的 3 个决策（默认方案）

1. **LLM 提供商**：默认 DeepSeek（性价比之王，官方 ¥2/M 输入、¥3/M 输出）；备选 通义千问（合规稳）/ GLM-Flash（免费额度）。
2. **数字人形态**：默认 2D Live2D 实时形象（免费、可交互、可私有化）；若追求真人级质感，升级腾讯智影/硅基智能实时数字人 API（付费，需企业资质）。
3. **目标市场**：默认先面向中国大陆学生（内容合规按国内要求做）；若考虑出海，英文内容与海外访问可无缝兼容（Cloudflare 天然全球化）。
